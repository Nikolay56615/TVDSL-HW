# HW3 — имена и типы Funny

Третье домашнее задание по курсу [TVDSL](https://github.com/nsu-fit/TVDSL).
Проверка использует парсер и AST из HW2: находит объявления, проверяет
области видимости и типы, выводит типы локальных переменных и добавляет
аннотации в дерево. Программы при этом не выполняются.

## Установка

Нужен **Python 3.10+**, сторонних зависимостей нет. Склонируйте или скачайте
репозиторий, перейдите в его каталог и проверьте интерпретатор. Если каталог
называется иначе, замените `TVDSL-HW` на его имя:

```powershell
cd TVDSL-HW
python --version
```

В Linux/macOS можно использовать `python3`, в Windows — `py`.
Таблица лексера уже находится в `HW1/generated/dfa.min.json`.
При необходимости её можно пересобрать: `python -m HW1.funnylex build`.

## Запуск

Все команды выполняются из корня репозитория:

```powershell
python -m HW3.funnytypes check HW3/examples/good_basic.funny
python -m HW3.funnytypes check HW3/examples/good_basic.funny --format tree
python -m HW3.funnytypes check HW3/examples/bad_types.funny --format tree
python -m HW3.funnytypes check --text 'f(x:int) returns r:int uses tmp { tmp = x + 1; r = tmp; }'
python -m HW3.funnytypes check HW3/examples/good_basic.funny --out typed_ast.json
python -m HW3.funnytypes test
python -m HW3.funnytypes test -v
python -m unittest discover -s HW3/tests
```

- `check` выводит JSON с полями `ok`, `ast`, `diagnostics`; `--text` задаёт текст вместо файла.
- `--format tree` показывает дерево с типами и координатами; `--out PATH` сохраняет результат в UTF-8.
- `test` проверяет случаи из `HW3/tests/cases.json`; `test -v` показывает исходники,
  ожидаемый и полученный результат, ошибки и сравнение заданных эталонов.
  Свой набор: `test --cases PATH -v`.
- `--table PATH` у `check` и `test` выбирает другую таблицу ДКА HW1.

PASS у негативного теста означает, что ожидаемая ошибка обнаружена.
Проверено **47/47 эталонных случаев** (20 позитивных, 27 негативных)
и **72/72 unittest** (41 проверка семантики, 24 CLI, 7 унификации).
В [examples/](examples/) есть 5 корректных и 3 ошибочных программы.
Коды завершения: `0` — корректная программа или все эталоны совпали;
`1` — ошибки программы или несовпадение эталона; `2` — ошибка запуска,
файлов, таблицы ДКА либо глубины вывода AST.

## Поддерживаемые проверки

Объявляемые типы Funny — `int` и `int[]`. Тип `bool` используется внутри
проверки для условий, предикатов и логических констант; объявлять переменные
`bool` или `string` нельзя. Правила записи программы остаются правилами HW2.

| Конструкция | Правило |
| --- | --- |
| Имена | функции и формулы уникальны в модуле; параметры, возвраты и локальные переменные уникальны внутри функции |
| Области | `requires` видит параметры; `ensures` — параметры и возвраты; тело и инвариант — также локальные переменные из `uses` |
| Параметры | доступны только для чтения, включая обновление элемента массива |
| Арифметика и сравнения | операнды `int`; результат арифметики `int`, сравнения `bool` |
| Логика | `not`, `and`, `or`, `->` работают с `bool`; условия и предикаты требуют `bool` |
| Массив | основа `int[]`, индекс и новое значение элемента `int`; `length(int[])` возвращает `int` |
| Вызов | число и типы аргументов точно совпадают с сигнатурой; поддержаны вызовы вперёд и рекурсия |
| Несколько результатов | вызов присваивается списку целей такой же длины; внутри выражения нужен один результат |
| Формула | вызов разрешён в предикате и возвращает `bool` |
| Квантор | связывает переменную только внутри своего предиката; её имя не должно совпадать с уже видимым именем |

Фигурные скобки `{ ... }` объединяют команды в блок. Локальные переменные
объявляются в `uses` перед телом функции и доступны внутри неё, в том числе
во вложенных блоках. Другие функции не могут обращаться к ним по имени.
Встроенная функция `length` принимает `int[]` и возвращает `int`.

Если тип локальной переменной не указан явно, проверяющий модуль определяет
его по первому **корректному** присваиванию:

```funny
f(x:int, input:int[]) returns r:int uses tmp, copy {
    tmp = x + 1;        // tmp: int
    copy = input;       // copy: int[]
    r = tmp + length(copy);
}
```

Далее тип должен сохраняться. Ошибочное `tmp = unknown;` не фиксирует тип,
а `uses a; a[0] = 42;` позволяет вывести `a: int[]` из контекста обновления.
Чтение локальной переменной до вывода её типа и случай `a = a;` дают ошибку.
Вывод идёт по порядку AST, включая обе ветви `if` и тело `while`, без анализа
того, какая ветвь выполнится.

## Python API и формат AST

```python
from HW3.funnytypes import check, check_ast
from HW2.funnyparse import parse

result = check('f(x:int) returns r:int uses tmp { tmp = x + 1; r = tmp; }')
print(result.ok)
print(result.to_dict())

parsed = parse('f() returns r:int { r = 1; }')
typed = check_ast(parsed.ast)       # аннотирует копию; parsed.ast не меняется
```

`check` объединяет лексические, синтаксические и семантические сообщения.
`check_ast` проверяет уже готовое дерево; диагностика предыдущего разбора
в него автоматически не переносится.

Сохраняются `kind`, `pos = {"line": ..., "col": ...}` и все поля HW2.
У выражений добавляется `inferred_type`: `"int"`, `"int[]"`, `"bool"`
или `"error"`; у вызова с несколькими результатами — список типов.
У `VariableDecl` исходное поле `type` сохраняется: для `uses tmp` оно равно
`null`, а выведенный `"int"` записан отдельно в `inferred_type`.
Сигнатуры функций и формул записываются в `signature` с полями `params`
и `returns` — списками типов. Такой AST можно передать следующему этапу HW4.

Семантическое сообщение содержит `phase="semantic"`, `code`, `line`, `col`
и понятный текст `message`. Позиции считаются с 1. Проверка собирает несколько
ошибок; тип `error` помогает не повторять следствия уже найденной ошибки.
Наличие частичного дерева при `ok=false` не делает программу корректной.

## Краткий отчёт: подход и ограничения

Сначала регистрируются все сигнатуры, затем проверяются контракты и тела.
Таблицы символов хранят имя, тип и право записи; поиск идёт по цепочке
лексических областей. Для локальных переменных без типа используется переменная типа
и простая унификация с `int`, `int[]`, `bool`. Тип фиксируется только после
корректного присваивания, несовместимость и невозможность вывода диагностируются.
Код разделён на [типы](funnytypes/types.py), [символы и области](funnytypes/symbols.py),
[обход AST](funnytypes/checker.py) и [API](funnytypes/__init__.py).

Проверяются имена и типы, но не истинность контрактов, завершение программы,
инициализация на всех путях, деление на ноль и границы массивов. Чтение явно
типизированной, но ещё не инициализированной переменной не отклоняется этим
проходом. Нет перегрузок, неявных преобразований, строк, массивных литералов
и объявляемого `int[][]`; вложенное индексирование `int[]` поэтому ошибочно.
Обновление массива в AST означает копирование по семантике Funny, но копия
при проверке не создаётся. Очень глубокое дерево ограничено стеком Python.
