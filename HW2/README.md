# HW2 — синтаксический анализ Funny

Второе домашнее задание по курсу [TVDSL](https://github.com/nsu-fit/TVDSL).
Парсер читает программу Funny, строит AST (дерево программы) и сообщает об ошибках.
Токены получает из лексера HW1; разбор написан рекурсивным спуском в `HW2/funnyparse/`.

## Установка

Нужен **Python 3.10+**, сторонних зависимостей нет. Склонируйте или скачайте
репозиторий, затем перейдите в его каталог и проверьте интерпретатор.
Если каталог называется иначе, замените `TVDSL-HW` на его имя:

```powershell
cd TVDSL-HW
python --version
```

В Linux/macOS замените `python` на `python3`, если требуется. Установка пакетов
и создание виртуального окружения не обязательны.

Таблица лексера уже есть в `HW1/generated/dfa.min.json`. При необходимости
её можно пересобрать:

```powershell
python -m HW1.funnylex build
```

## Запуск

Все команды выполняются из корня репозитория:

```powershell
python -m HW2.funnyparse parse HW2/examples/good_basic.funny
python -m HW2.funnyparse parse HW2/examples/good_contracts.funny --format tree
python -m HW2.funnyparse parse HW2/examples/good_arrays_and_tuple.funny --out ast.json
python -m HW2.funnyparse parse --text 'f(x:int) returns r:int { r = x + 1; }'
python -m HW2.funnyparse parse HW2/examples/bad_recovery.funny --format tree
python -m HW2.funnyparse test
python -m HW2.funnyparse test -v
python -m unittest discover -s HW2/tests
```

- `parse` выводит JSON с полями `ok`, `ast`, `diagnostics`. `--text` читает строку вместо файла.
- `--format tree` выводит дерево с отступами; `--out ast.json` сохраняет результат в файл UTF-8.
- `test` проверяет 25 случаев из `HW2/tests/cases.json` и печатает итог.
- `test -v` показывает каждый тест: номер, название, программу, ожидаемый и полученный
  результат, сообщения об ошибках. Если задан эталон AST или диагностики, показывает
  результат сравнения; при отличии AST — первое несовпавшее поле. Свой набор: `test --cases PATH -v`.
- `unittest` запускает 53 теста парсера и командной строки.
- `--table PATH` у команд `parse` и `test` выбирает другую таблицу ДКА HW1.

У ошибки есть этап (`lexical` или `syntax`), строка, столбец и сообщение.
Нумерация начинается с 1; LF, CRLF и CR учитываются одинаково.
После синтаксической ошибки парсер ищет следующий оператор или объявление,
чтобы разобрать оставшуюся часть программы. В AST могут остаться узлы `Error`.
Например, в `r = ; r = 2;` первое присваивание даёт ошибку, а второе попадает в дерево.

## Вызов из Python

```python
from HW2.funnyparse import parse

result = parse('f() returns r:int { r = 1; }')
print(result.ok)
print(result.ast)          # дерево: словари и списки
print(result.to_dict())    # тот же результат, что выводит команда parse
```

У каждого узла есть `kind` и `pos = {"line": ..., "col": ...}`.
Например, у `Binary` поля `op`, `left`, `right` хранят оператор и два поддерева.

## Грамматика и дерево

Правила и ограничения записаны в [grammar.ebnf](grammar.ebnf).
Парсер разбирает функции и формулы, контракты, локальные `uses`, присваивания,
`if`/`else`, `while`, блоки, `assert`/`assume`, кванторы, вызовы и массивы.

Приоритет от сильного к слабому: унарный `-`, `* /`, `+ -`, сравнения,
`not`, `and`, `or`, `->`. Например, `1 + 2 * 3` строится как `1 + (2 * 3)`,
а `10 - 3 - 2` — как `(10 - 3) - 2`. Импликация группируется справа:
`true -> false -> true` означает `true -> (false -> true)`.
Цепочки вроде `1 < 2 < 3` запрещены.

`else` относится к ближайшему `if` без `else`. Если контракт не указан,
в дерево подставляется `requires=true`, `ensures=false`, `invariant=true`.
`a[i] = v` записывается как `Assign(a, ArrayUpdate(a, i, v))`: обновление
обозначает создание копии массива. Для `a[i][j] = v` строятся вложенные обновления.
В `x,y = f()` справа должен быть один вызов; скобки `x,y = (f())` допустимы.

Допустимые формы записи:

- Функцию можно записать как `f(...)` или `function f(...)`.
- `requires` допускается один раз: перед `returns` или после него.
- У объявления формулы завершающий `;` необязателен.
- Типы объявлений — `int` и `int[]`. Имена — ASCII с подчёркиваниями, как в HW1.
- Стрелки `→` и `->` дают один оператор `->` в AST. В комментариях разрешён Unicode.

Арифметика, условия и предикаты проверяются отдельно: `if (1)` и `assert x`
дают ошибку; `if (x > 0)` и `assert positive(x)` допустимы.
Сам вызов `if (positive(x))` условием не считается. `length(a)` — арифметика.
Проверять, объявлено ли имя, подходят ли типы и число аргументов/результатов,
будет HW3.

В [examples/](examples/) есть 5 корректных и 5 ошибочных программ.
Тесты проверяют структуру дерева, приоритеты, позиции, продолжение разбора
после ошибок и завершение разбора на некорректном вводе.

Коды завершения: `0` — корректная программа или все тесты прошли;
`1` — ошибки программы или несовпадение эталона; `2` — ошибка аргументов,
чтения/записи файлов, таблицы ДКА или ограничение глубины сериализации AST.
