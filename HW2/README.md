# HW2 — синтаксический анализ Funny

Второе домашнее задание по курсу [TVDSL](https://github.com/nsu-fit/TVDSL). Использует лексер из соседней папки HW1.

## Установка

Нужен **Python 3.10+**, сторонних зависимостей нет. Склонируйте или скачайте
репозиторий, затем перейдите в его каталог и проверьте интерпретатор.
Если каталог называется иначе, замените `TVDSL-HW` на его имя:

```powershell
cd TVDSL-HW
python --version
```

В Linux/macOS замените `python` на `python3`, если требуется. Установка пакетов
и создание виртуального окружения не обязательны.

Таблица лексера уже сохранена в `HW1/generated/dfa.min.json`. Чтобы пересоздать
её, выполните из корня репозитория:

```powershell
python -m HW1.funnylex build
```

## Парсер, AST и диагностика

`HW2/funnyparse/` содержит рекурсивный спуск для Funny, интегрированный с таблицей
лексера HW1. Финальная грамматика и правила разрешения неоднозначностей —
[grammar.ebnf](grammar.ebnf). Генератор парсеров не требуется.

```powershell
python -m HW2.funnyparse parse HW2/examples/good_basic.funny
python -m HW2.funnyparse parse HW2/examples/good_contracts.funny --format tree
python -m HW2.funnyparse parse HW2/examples/good_arrays_and_tuple.funny --out ast.json
python -m HW2.funnyparse parse --text 'function f(x:int) returns r:int { r = x + 1; }'
python -m HW2.funnyparse parse HW2/examples/bad_recovery.funny --format tree
python -m HW2.funnyparse test
python -m unittest discover -s HW2/tests
```

По умолчанию `parse` печатает UTF-8 JSON: `ok`, `ast`, `diagnostics`.
`--format tree` показывает дерево и сообщения; `--out` записывает результат
в файл. Ошибки содержат этап (`lexical`/`syntax`), строку, столбец и сообщение.
После синтаксической ошибки парсер восстанавливается на границе оператора
или объявления и возвращает частичный AST с узлами `Error`.
`--table PATH` позволяет подключить другую таблицу ДКА HW1;
`test --cases PATH -v` запускает свой набор эталонов и печатает каждый результат.
По умолчанию HW2 читает таблицу `HW1/generated/dfa.min.json`.

Поддерживаются функции с `returns`, `requires`/`ensures`, локальные `uses`,
формулы и кванторы, присваивания и кортежи, `if`/`else`, `while` с `invariant`,
блоки, `assert`/`assume`, вызовы, `length`, чтение и обновление массивов.
Обновление `a[i] = v` превращается в `Assign(a, ArrayUpdate(a, i, v))`;
вложенные индексы дают вложенные функциональные обновления с копированием.
Приоритеты: унарный `-`, `* /`, `+ -`, сравнения, `not`, `and`, `or`, `->`.
Импликация ассоциируется справа, остальные бинарные операции — слева;
цепочки сравнений запрещены. `else` относится к ближайшему `if`.
Отсутствующие `requires`, `ensures`, `invariant` означают `true`, `false`, `true`.

API для следующих ДЗ:

```python
from HW2.funnyparse import parse

result = parse('f() returns r:int { r = 1; }')
print(result.ok)
print(result.ast)          # словари/списки; у каждого узла kind и pos={line, col}
print(result.to_dict())    # JSON-совместимый результат с диагностикой
```

Совместимость с материалами курса:

- Принимается `f(...)` из спецификации и `function f(...)` из практики P03.
- `requires` допускается перед `returns` и после него; повторение — ошибка.
- У формулы допускается завершающий `;`, как в примерах проекта.
- Подчёркивания в именах сохранены из HW1; объявления имеют тип `int`/`int[]`.
- Импликация допускает `→` и `->`; в AST обе формы представлены оператором `->`.
  Имена используют ASCII, комментарии допускают Unicode. Таблица и поведение первого ДЗ сохраняются.
- Позиции корректны для LF, CRLF и CR. Строки и столбцы начинаются с 1.
- Проверки имён, типов переменных, сигнатур вызовов и числа возвращаемых значений относятся к HW3.
  Парсер проверяет синтаксическую форму арифметики, условий и предикатов.

Проверки HW2: **25 эталонных случаев и 50 модульных/CLI-тестов**;
в `HW2/examples/` есть 5 положительных и 5 отрицательных программ.
Тесты сравнивают AST с эталоном, проверяют приоритеты, позиции,
восстановление после ошибок и отсутствие зацикливания.

Коды завершения: `0` — корректная программа или все тесты прошли;
`1` — ошибки программы или несовпадение эталона; `2` — ошибка аргументов,
чтения/записи файлов, таблицы ДКА или ограничение глубины сериализации AST.
